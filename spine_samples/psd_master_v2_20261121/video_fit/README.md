# PSD 右前行走候选 · 2026-11-21

本包是固定 PSD 母版的第一次完整行走试装，尚未获得用户视觉验收，也不代表工作台已支持自动解析任意新视频。

## 查看方式

1. 完整解压包，在 Spine 4.2.43 打开 `psd_walk_candidate.spine`。
2. 切换到动画模式，选择 **video_walk_fit**，开启循环播放。不要停留在设置模式或 setup_hold。
3. `test_` 开头的五个动画保留用于关节检查。
4. 浏览器预览需 HTTP 服务：在解压目录运行 `py -3 -m http.server 8771 --bind 127.0.0.1`，访问 `http://127.0.0.1:8771/review.html`。
5. 可暂停逐帧、半速、显示骨骼，切换手脚局部与 PSD 静态对照。日志固定高度。

## 来源与结构

- 七张贴图均来自用户提供的《右前图层.psd》，与本次 PSD 静态母版 PNG 的 SHA256 一致；没有旧逐帧拆件、AI 补画或新增纹理。
- PSD SHA256：`6b4cc52ada9e3c71ab4c6e8ef53f2857ac72c82cb105907259d64a81e76b4f50`。裁切与边缘杂点处理见 source_manifest.json；原 PSD 未修改。
- 动作使用已验收 pixel_sync_20261120 的 reference_cycle 第 63–85 帧轨迹；按新素材的长度与静态方向重定向，非照搬旧坐标。
- 20 根骨骼、4 组双骨 IK、7 个固定网格附件。原 16 根结构外增加 2 根脚掌控制和 2 根 IK 膝关节驱动的形体控制骨，不增加贴图。
- 仅一张 1468 × 480 图集；RGBA 解码约 2.69 MiB，不含 mipmap 与运行时额外开销。
- 四肢摆动角度保持参考轨迹的角幅；长度变化包含透视缩短，不能全解释成关节弯曲。故伸展范围约束为手臂总长的 96%–98.5%、腿的 93%–98.5%，具体记录见 provenance.json。
- 膝关节形体控制采用仅继承平移，以平滑权重连接固定腿根与脚掌，避免宽厚肢体在大角度时折叠。实际 IK 仍驱动膝和踝，但皮肤横截面不会完全跟随骨骼旋转。

## 已完成检查

Spine 4.2.43 导入为真实工程，再导出 JSON，使用官方运行时检查回导结果。93 次循环采样（每源帧含四分之一帧），最大顶点差约 0.0467 px，IK 端点差小于 0.000001 px，首尾顶点差为 0，网格翻折为 0。23 个关键姿势全部渲染；总览为 contact_sheet.jpg。

## 尚未完成，不能视为生产验收

- 尚未独立标注支撑/摆动阶段，未完成落脚、滑步与速度连续性验收。首尾位置吻合不代表速度连续。
- 宽厚腿部弯曲量做了限制，动态可能比视频硬；裤口局部轮廓、远侧手肩根及交叉步形体需用户检查。
- 头部保持当前 PSD 原貌，包括左侧棕绿色区域；未拿视频头部替换，也未修图。
- 尚无衣物 skin 实测、第二动作复用验证或 05 工作台生产集成。
- 下一步按视觉反馈校正接触阶段与权重；母版确认后再做同骨架换装与第二动作，最后接回自动化流程。

## 复现

项目内依次运行 extract_motion.cjs → fit_video.py → bind_walk.cjs，再用 Spine CLI 导入新文件名的工程并回导到 roundtrip，执行 verify_walk.cjs、render_walk.py。不要反复导入已有工程，避免合并重复骨架。`verify_walk.cjs --draft` 仅为导出前的几何排查，不计为回导验收。
