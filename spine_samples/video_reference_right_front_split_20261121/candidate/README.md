# 新视频 × PSD 右前行走候选

本包尚未获得用户视觉验收。技术检查通过不代表动作、裤口或遮挡效果已合格。

## 查看顺序

1. 先打开在线 review.html，按正常速度和 1/4 速度查看三栏对照。
2. 勾选“手脚局部”，逐帧核对 59–82。中栏为新轨迹驱动的骨骼，右栏是固定 PSD 附件。
3. 重点检查 59–62、78–82 的后摆脚与裤口；65–74 的远侧脚被遮挡，橙色目标是推断值。
4. 在 Spine 4.2.43 中打开 `right_front_split_psd.spine`。切到动画模式，激活 `video_right_front_split_59_82`，开启循环播放。
5. `psd_bind_pose` 仅用于检查绑定姿势，故意保持静止。本工程没有旧视频的 `reference_cycle`。

解压后保留 `parts/` 与 `.spine` 的相对位置。review.html 需要通过本地 HTTP 服务打开，例如在解压目录运行 `py -3 -m http.server 8771` 后访问 `http://127.0.0.1:8771/review.html`。

- 视频：用户提供的 `右前行走-拆图层.mp4`，864×480、24 fps。
- 区间：2.458333–3.458333 秒，即源帧 59–82；第 83 帧是结束边界，不重复取入。
- 原画：`右前图层.psd`，SHA256 `ba7c6d3b0b1bb1c5521184257c2f2f2592eda9f098ee4a2e04e1eb8a6ebbe8cd`。
- 皮肤：此前从该版 PSD 提取的七张固定裁片，本轮 SHA 全一致，未补画、未调色、未使用旧视频逐帧附件。原提取时的透明边裁切记录保留在 source_manifest.json，不宣称这些裁片覆盖 PSD 的所有低透明度杂点。
- 原视频帧只放在 `reference_frames/` 用于审阅，不进入皮肤或图集。

## 与 pixel_sync_20261120 的关系

保留 16 根骨骼的名称和父子层级，以及四组双骨 IK 的对象、顺序、弯曲方向、mix、stretch、compress 等规则；实际回导后的运行时 IK 参数已逐项比较。

这不是旧骨架坐标、旧动画的逐字副本。静态骨长、根部和绑定姿势按当前 PSD 重新标定；原始 PSD 在绑定姿势中只做统一相似变换，没有对单只脚做非均匀拉伸。

头部运动使用新视频图像特征匹配；四肢使用 9 个关键姿势的可见端点标注及 PCHIP 插值。髋点、肘膝不是由视频精确恢复的隐藏解剖位置；髋根保持与躯干/裤衩一致的绑定关系。遮挡手脚在 motion_observations.json 中明确记为不确定。

为了适应前后摆动的二维投影，四肢包含长度缩放轨道：手臂沿链方向变化；腿链采用统一缩放以避免非均匀 IK 扭曲。脚掌区域（PSD y≥825）100% 绑定目标骨，目标骨不继承腿链缩放，因此脚掌内部距离保持不变。脚掌朝向由肢体轴方向估计，并非独立恢复的足部三维姿态。

没有新增骨骼、逐帧换图或逐帧补画。七张贴图与同一动作复用；此小样仍有人工标注步骤，尚未接入 05 的 PSD 全自动制作入口。

## 技术检查

- 真实 `.spine` 已通过 Spine 4.2.43 CLI 导入与 JSON 回导。
- 97 个采样时间，包含 24 个源帧和帧间位置；网格翻折 0。
- 回导顶点最大偏差约 0.0986 px；IK 骨端与目标最大偏差约 0.000104 px。
- 脚掌内部距离最大变化约 0.000013 px；首尾顶点差 0。
- 以上是几何及回导一致性检查，不能证明关节推断、遮挡关系、地面接触或美术完全正确。
- 24 帧整体与局部对照已经生成；浏览器实测播放、逐帧、局部放大、骨骼叠加及循环边界。
- 图集：1 张 1460×480，基础 RGBA 约 2.67 MiB。尚未做换装与手机运行时验收。

原视频 82→59 的前景 RGB 平均绝对差约 15.89，片内相邻帧中位值约 16.66；83→59 为 6.02。该数值支持继续使用用户所选区间，不代表原视频像素完全闭合。

## 仍需视觉判断

PSD 和 AI 视频的颜色、头部细节、短裤轮廓本来就存在差异，本轮保留 PSD 外观。优先判断步态、脚掌、裤口与大腿连接是否达标，不将贴图像素差异误当作骨架误差。

中段远侧脚轨迹属于遮挡估计。固定附件可复用与逐帧还原视频细节是不同的质量目标；本包只是一份可检查的固定附件候选，不是已验收的换装生产模板。
