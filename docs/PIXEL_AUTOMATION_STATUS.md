# 05 自动生成开发状态（2026-11-20）

本轮接入真实视觉识别与自动候选生成，尚未达到自动产出合格 Spine 的验收目标。

## 用户入口

导入视频并选择帧区间 → 自动识别部件与骨骼 → 自动生成可运行的动画候选 → 对照原视频查看异常 → 无异常后整段视觉验收 → 导出 Spine。
识别结果不写入逐部件人工审核标志。高级轮廓与锚点工具仍可用于纠错。

## 实际实现

- pixel_automation.py 通过已配置的 ARK_BASE_URL / ARK_API_KEY 调用视觉模型，默认 doubao-seed-2-1-pro-260915，可用 PIXEL_VISION_MODEL 配置。
- 按实际源帧识别 7 部件、10 锚点、4 肘膝，明确归一化坐标后转换到原分辨率；没有读取验收样板的标注或遮罩作为识别输入。
- 均匀背景分离；局部轮廓延展只取当前帧已有前景 RGB，记录延展数量及部件归属歧义。不生成隐藏像素，不补画。
- 全段投影骨长中位数和固定弯曲方向拟合；保留原始模型响应。拟合大幅偏离检测结果时阻止验收，不能把反向绑定后皮肤正确当作关节识别正确。
- 后台任务、逐帧缓存、重启提示、版本冲突保护；生成期间编辑不会被覆盖。
- 输入指纹绑定自动候选与验收；手工保存会废弃自动验收，快照保留旧记录。
- 运行时合格但语义存在异常的候选可预览，不能通过整段验收或导出。

仅测试了原视频的三帧；没有证明完整周期或新视频可自动合格。当前不支持复杂背景、多角色、明显视角切换。遮挡关节仍是 2D 推定。基准样板本身的肘膝也是拟合值，不是独立测得的解剖真值。

## 规范与检查分层

1. 格式/绑定规范：7 部件、16 骨骼、4 双骨 IK、源帧附件与骨骼 stepped 同步、reference_cycle、Spine 4.2.43 导入回导。
2. 来源规范：原视频和帧 SHA，原 RGB 不变，保留模型输出及坐标空间，禁止跨视频复用旧标注。
3. 质量候选检查：前景覆盖、部件缺失、端点像素支持、方向翻转、骨长/端点跳变、时序拟合偏差。当前像素支持依赖预测遮罩，不能当作独立语义真值。
4. 最终视觉验收：用户对照原视频检查部件归属、裤衩遮挡、远侧手和动作。不能被技术检查自动替代。
