## 二、PSD 到 Spine 的实际全流程

### 1. 固定素材版本，先检查分层是否适合运动

登记 PSD 与视频的完整路径、SHA256、PSD 画布、图层名、层级、透明边界、原画位置以及视频帧率。路径相同不意味着文件相同；用户修改脚部图层后必须重新读 PSD 和计算版本。

本版 PSD SHA256：`ba7c6d3b0b1bb1c5521184257c2f2f2592eda9f098ee4a2e04e1eb8a6ebbe8cd`。

本版视频 SHA256：`93d00de73120801f73de8cd723973fb4ec1d5b4a887ba1a5fa5e63772ad6f3ff`。

图层对应关系来自 `source_manifest.json`：

| PSD 图层 | 逻辑部件 | 绑定用途 |
|---|---|---|
| `headwear` | `head` 头部 | 跟随头部控制 |
| `topwear` | `torso` 躯干 | 躯干骨骼与下腹表面过渡 |
| `bottomwear` | `shorts` 裤衩/骨盆外观 | 骨盆为主，裤口随腿部过渡 |
| `handwear-r` | `arm_near` 近侧完整手臂 | 上下臂链；本图通常为画面左侧 |
| `handwear-l` | `arm_far` 远侧完整手臂 | 上下臂链；本图通常为画面右侧 |
| `legwear-r` | `leg_near` 近侧完整腿脚 | 骨盆、上下腿与脚部目标控制过渡 |
| `legwear-l` | `leg_far` 远侧完整腿脚 | 同类绑定，单独处理远侧遮挡 |

近/远侧是语义身份，不能随画面位置交叉而互换。图层名只是本样板映射，不应当成适用于所有 PSD 的硬编码规则。

**拆图层与拆骨骼是两件事。** 一张完整手臂可以由上臂、前臂两根骨骼共同驱动，不要求美术在肘处切断；一张完整腿脚也可以有多骨权重。优先保留连续原画，减少人为切口。

静态检查要看双腿是否独立、肩根/腋下/腿根是否完整、原组装位置是否保留、裤口是否能与腿根重叠。动态检查还要看最大摆幅时是否露缺口。透明度检查只能发现已有像素的边界，不能证明被遮挡的表面画全了。

### 2. 导出固定裁片，保留画布坐标和裁剪记录

从 PSD 导出 7 张 RGBA 裁片，记录图层原始包围盒、层内裁剪框、画布坐标框及输出 SHA。所有后续配准使用画布坐标，而非把每张裁片的左上角当成共同原点。

准确的原像素声明是：**本版保留区域的 RGBA 未修改，输出七张纹理在 r2→r3 中保持一致。** 不能写成“PSD 的全部非透明像素均完整保留”：源清单记录裁剪框外确有非零 alpha 像素，例如头部 11,902 个、最大 alpha 151；躯干 22,749 个、最大 25；裤衩 33,474 个、最大 24。此次最终裁片已随动画获验收，但工作台泛化导入必须显示被裁区域叠图并允许用户检查，不能把这些数值直接当成通用裁剪阈值。

产物：`parts/*.png`、`source_manifest.json`、`skin.atlas`、`skin_0.png`、`atlas_report.json`。

### 3. 选动作区间，统一时间与坐标

按用户选段提取 59–82 帧并逐帧记录哈希；使用 83 帧作边界参考，不把它作为第 25 个视频帧导入。动画时间为 `(源帧−59)/24`，在 1 秒处写入回到首姿势的闭环键。

源片末尾与首帧不一定天然一致，因此既要看闭环键的几何连续，也要看 82→59 的步态节奏。首尾顶点差为 0 本身不证明速度连续或没有脚滑。

PSD 与视频通过注册矩阵对齐比例、旋转和位置；从图像向下的 Y 轴换成 Spine 向上的 Y 轴。头部使用图像特征拟合，四肢使用关键姿势观察。不能直接拿旧视频的坐标驱动新 PSD。

### 4. 复用骨架规则，重新标定绑定姿势

复制已验收 `pixel_sync_20261120` 的骨骼层级、IK 对象、执行顺序与弯曲方向，按新 PSD 重新设置肩、髋、端点位置及静态骨长。保留的是结构规范，不是逐字相同的骨骼定义、旧动作轨迹或旧附件。

检查静态蒙皮是否能还原 PSD 组装图；先排除坐标、比例和绘制层级问题，再调动画。四组双骨 IK 分别控制近/远手臂和近/远腿。

2D 中肢体朝镜头方向摆动会缩短投影长度，强制投影骨长不变会造成膝肘过弯。本版最终用上骨统一缩放、下骨纵向缩放拟合投影；这是二维表现，不是恢复真实三维骨长。新的动作仍需检查缩放与拉伸。

### 5. 观察关键姿势，建立表面和关节的共同参照

本版在 59、62、65、68、71、74、77、80、82 帧人工观察四肢与裤衩的轮廓控制点，以 PCHIP 插值补齐中间帧，以平滑薄板样条（TPS）将 PSD 表面映射到目标轮廓。

肩/髋、手脚端点、膝肘参照点均对应同一份 PSD 材质坐标。完全遮挡的关节不是可直接测量的真值，必须记录推定；不能用“皮肤对齐”代替骨骼姿态独立检查。

产物：`motion_observations.json`、`surface_fit.json`。这些数据含人工标注，是工作台首先需要改造成可编辑数据的部分，不能继续藏在脚本坐标常量中。

### 6. 建网格、赋权重，处理部件交界

本版使用规则网格：四肢 12×24、裤衩 20×12、躯干 12×12、头部 1×1 网格单元。此密度是样板实现，不是所有角色都要照抄的生产预算。

手臂在上/下臂之间过渡；腿根混合骨盆权重，向上下腿及脚部目标过渡；裤衩以骨盆为主、裤口适量随上腿，避免整件裤衩硬转或被腿拉成尖角。绘制顺序也要与近/远肢体及裤口的遮挡匹配。

r3 的决定性修订是：**裤衩与近侧大腿共享同一个外轮廓交界目标**；裤衩外侧新增两处控制点；裤衩/腿的源轮廓参照对齐 PSD alpha 边界。这样两块表面同时修正，避免单独移动裤角后把尖角推到大腿中段。

本版没有保留“强制把脚掌吸附到视频二值轮廓”的实验，因为它带来边缘波纹。后续也不能仅为降低轮廓误差而损坏原画。

### 7. 同步求解 IK 与网格残差

顺序必须明确：表面目标 → 对应材质锚点 → IK 拟合 → Spine 存储精度量化 → 基于最终骨骼姿态重算 deform。

IK 目标与表面必须来自同一组参照。先让骨架承担主要运动，再将拟合表面与当前蒙皮结果的差转换为每个加权骨骼局部空间的 deform 偏移。只改 IK、不更新表面残差，会再次让骨骼和皮肤错位。

重算时先清除旧 deform，避免重复叠加；量化后再算残差，避免 Spine 回导时因精度变化产生偏移。本版六个附件有 deform，脚掌也参与表面变形，不再是早期版本的刚性脚。

**这一版包含动作专用修形。** 把骨骼动画交给另一个附件，并不会自动继承相同表面效果；这也是换装需要独立验证的主要原因。

### 8. 导出、回导和技术检查

真实 Spine 4.2.43 每次导入到全新 staging 工程，断言只有一个骨架，再回导 JSON。不要对已存在的同名工程反复导入，否则可能追加多个骨架并误看旧结果。

| 检查 | r3 结果 | 解释 |
|---|---:|---|
| 采样时间点 | 193 | 覆盖源帧与帧间插值 |
| 网格翻折观察 | 0 | 检查范围内未翻折，不替代视觉检查 |

### 9. 视觉验收与归档

检查页并列原视频、骨骼叠加、PSD 蒙皮；提供全部 24 帧逐帧、手脚局部、网格、帧间插值和速度控制。日志固定高度，播放不挤动画布。重点核对裤口/裆部、腿根遮挡、脚掌形状、远侧手臂、接地脚滑和循环接缝。

用户本轮已通过视觉验收。登记具体素材哈希、动画、版本和证据，再打包 `.spine`、运行时 JSON/atlas/PNG、固定附件、参考帧、预览、来源记录、技术报告和 SHA 清单。后续任何重建均作为新候选，不能自动继承本次验收。

## 三、工作台 05 应怎样接入

### 产品入口与用户操作顺序

05 保留两条明确的资产路线：已有“视频原帧还原”和新增“PSD 固定部件动画”。前者服务视频像素对照；后者作为本次验证后的可复用资产路线。不能悄悄把同一个项目从固定附件切回逐帧贴图。

新增路线建议让用户只面对六步：

1. **导入角色 PSD**：选择朝向，自动识别图层并显示组装图；只在命名歧义、裁剪或缺像素时要求确认。
2. **导入 AI 视频并选段**：自动建议循环，允许手动改帧；预览区明确“结束帧包含”，内部统一为结束不包含，避免少一帧/多一帧。
3. **检查骨架与关键姿势**：系统提出绑定和姿势，默认先显示皮肤叠加；低置信度和遮挡点集中提示，允许拖动修正。
4. **生成动画并局部修正**：系统执行网格、权重、共享交界、IK 与 deform 同步求解；问题定位到部件和帧，而不是要求用户重跑全部。
5. **整段审阅**：播放、逐帧、对照、技术诊断与待决问题放在同一个固定布局内；检查包可供 Spine 复核。
6. **验收和导出**：技术通过后生成待验收包；人工确认绑定该版本；修改输入立即撤销该版本的可交付标记，再导出新候选。

目标是“常规步骤自动完成，异常集中确认”，不是声称本样板已经证明任意 PSD/视频一键完成。也不要求用户日常编辑脚本或手填坐标表。

## 四、换装如何做，为什么现在比逐帧附件更有基础

固定七张裁片使纹理不再随每个动作的帧数增长，具备建立角色资产库的基础。但本版 `topwear`/`bottomwear` 只是图层名，不能据此认定已拥有完整裸身、所有衣物或所有隐藏面；当前 `atlas_report.json` 的 `wardrobeReady=false` 应继续保留。

旧 `reusable_wardrobe_20261121` 实验未通过身体复用质量门。本次 r3 的通过不自动使该实验通过，也不证明 r3 身体可承受所有动作。应基于新 PSD 再做换装验证。

### 三类服装，采用不同适配方式

| 类型 | 推荐做法 | 必须验证 |
|---|---|---|
| 相同轮廓、同一网格的花纹/材质替换 | 同一 skin placeholder 下切换材质附件；条件满足时用 linked mesh 共用网格/权重，并明确 deform 继承 | UV、顶点顺序、三角形、尺寸/局部坐标兼容；Spine 4.2 实际换肤与 deform 生效 |
| 贴身但轮廓不同的上衣、裤子、袖子 | 同一骨架/动作，衣物独立网格与权重；由身体材质对应点和交界约束生成衣物适配 | 身体的 deform 不能按数组复制；须重新映射并对动作补充衣物修形 |
| 裙子、外套下摆、宽松/悬垂配件 | 固定身体骨架，衣物按需要增加有限的辅助骨/变形规则 | 穿插、遮挡与开销；超出 16 骨基础规范时单独登记，不无限加骨掩盖问题 |

在 Spine 中骨骼动画可由同一 SkeletonData 的皮肤共享，但 deform 针对具体附件/网格。**“同一 slot 换图就能复用全部动画效果”只在相容结构下成立。** 换装验证必须包含非零时间点、换 skin 后恢复槽位、动画中的 attachment/deform 键是否覆盖了当前服装、卸装后是否恢复正确身体附件。

组合换装建议按上衣、下装、帽饰、鞋等分类建立可组合 skin；身体与衣服分开管理 slot/覆盖规则，需要时将一件服装分成前后片或近远袖。不要为每套服装复制整个头/手/脚，也不要把颜色与服装的笛卡尔组合预烘焙成完整角色套图。遮挡身体时可按明确规则隐藏部分身体附件；卸装与大摆幅时仍需有真实可用身体素材。

### 第一套换装的最小验证

1. 检查本版 PSD 在抬手、迈腿、卸装时所需身体像素是否完整；缺口列图，由用户提供正确图层，不能偷偷补画。
2. 用与当前 PSD 同朝向、同组装坐标的一套衣服，优先贴身上衣/短裤，暂不选长裙或大外套。
3. 在已验收行走动作上验证身体 → 穿衣 → 卸装以及近远袖、腰口、裤口的整段接缝。
4. 再用同朝向第二个动作测试同一套纹理、网格与服装规则。行走复制/减速不算第二动作。
5. 输出对照表：新增纹理数、图集页/尺寸、基础 RGBA、mesh 顶点/三角形/权重影响数、deform 数据大小、目标设备开销与视觉结论。

资源规模应主要随“朝向数与独立服装数”增长，而不随“每动作帧数×服装组合数”增长。基础身体、常驻配件与可选服装可按实际加载范围分 atlas；多张 PNG 本身合理，判断依据是同时驻留内存、纹理切换与 draw call。是否使用运行时重打包需结合 Spine/Unity 版本实测，不能预先承诺性能。

## 五、角色其他朝向如何做

沿用项目已有六方向设计：**四套源方向——正面、背面、右前 ¾、右后 ¾；左右 ¾ 在允许时镜像，覆盖六个运行方向。** 不额外强迫制作六套完全独立美术，也不认为镜像必定正确。

| 朝向 | 美术与绑定 | 可复用内容 |
|---|---|---|
| 右前 ¾ | 本次已验收基准；新增动作另行拟合 | 该 PSD 版本的固定纹理与静态角色配置，需验证动作范围 |
| 左前 ¾ | 无方向性文字/装饰/功能性不对称时优先镜像右前 | 播放和相位逻辑；镜像后近远身份、IK 弯曲、遮挡和接地需检查 |
| 右后 ¾ | 新朝向分层 PSD + 相应视频 + 独立标定 | schema、命名、构建、审查和导出工具；旧右后视频逐帧验收不能替代 PSD 版验收 |
| 左后 ¾ | 满足外观条件时镜像右后 | 同左前镜像规则 |
| 正面/背面 | 各自美术和绑定配置，优先待机/互动 | 通用工作流；不能直接复用 ¾ 的坐标、权重或轨迹 |

存在文字、胸章、单侧配件或不对称花纹时，对应衣物/角色要提供独立方向资产或镜像修正资源。不能为了节省图集把本应不对称的设计反过来。

资产库建议以 `character + view + artRevision` 管理视觉 rig，各方向共享语义骨骼命名和动画名，但允许各自静态坐标、网格、权重和绘制顺序。应用层以一个角色控制器驱动当前方向；不要求所有方向共用同一份变形数据。

行走转向需要脚步相位映射：右脚接地的时刻切到另一方向对应的接地相位，而不是一律重播第 0 帧。根部/地面锚点、画面尺度和接地高度需统一。第一阶段可做经过检查的离散转向；平滑 ¾→背面连续旋转需要额外转身素材或过渡动画，不能靠两个平面附件硬拉得到。

正背面待机、前后 ¾ 行走先组成最小方向集，跑步、坐下、躺下和睡觉再按实际遮挡范围逐项验证。确需额外手势/表情/视角附件时使用有限、具来源记录的状态，并统计预算，不回退到每帧整套皮肤。

## 六、建议下一次实际开发范围

**先做 P1：将已验收 r3 的制作数据和 PSD 导入能力接入独立的固定部件模式，完成可复现重建与对照。** 随后接 P2，把这一个案例真正变成工作台内可操作的全流程；再用 P3 验证第二动作和服装复用，避免先大规模制造服装或多方向素材。

P1 可以使用现有 PSD、视频和标注启动，暂不需要用户额外制作素材。到 P3 前再收集：与当前身体匹配的完整服装 PSD、一个独立同朝向动作、目标引擎/设备和大致同屏数量；到 P4 前收集右后 ¾ 分层 PSD。旧服装原画只能作为备选来源，不能直接算已匹配当前 PSD。

本轮完成的是验收登记、交付包元数据更新与方案整理；尚未实施上述工作台模块，也未提交或推送 Git。
