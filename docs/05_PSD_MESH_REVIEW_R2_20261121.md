# PSD 网格、蒙皮与 IK 复核 r2

用户提供的六个截图暴露出 r1 裤口刚性、腿根突出与脚掌姿态偏差。本轮独立候选位于 `spine_samples/video_reference_right_front_split_20261121/candidate_r2`，未修改已验收 pixel_sync 样板，未接入正式自动生成入口。

## 完成项

- 对源视频 59–82 全 24 帧及 9 个人工关键姿势进行对照。
- 7 张 PSD 纹理 SHA 一致，图集仍 1460×480 单张，无新贴图、补画或调色。
- 裤衩网格 20×12，躯干 12×12，四肢 12×24；调整腿根、裤口和下腹连接权重。
- 6 个部件添加 source-observed contour cages 驱动的 Spine 4.2 `attachments.default.<slot>.<attachment>.deform` 时间线。固定 PSD 图像的形状变换用于接近原视频轮廓。
- 四组 IK 的端点改为同一 PSD 材质点随轮廓映射的位置。膝肘遵循原基线的弯曲方向，内部关节为估计，并非真正的视频解剖标注。
- 保留 16 骨骼 / 4 IK 的层级和约束参数，按 PSD 标定静态比例。
- 浏览器提供骨骼和网格叠加、24 帧逐帧、严格同帧播放及可选帧间插值。日志固定高度。

## 验证

真实 Spine 4.2.43 导入、回导；193 个时间点，0 翻折，回导顶点差 0.01163 px，绑定姿势配准差 0.000014 px，IK 链端误差 <0.000001 px，首尾网格顶点差 0。材质锚点与网格内部一致性差约 0.114 px。

白底二值下身轮廓对比（ROI x340:540/y335:438，包含部分手部）在三个阈值下均较 r1 改善，阈值 240 下平均 IoU 从 0.802 提升到 0.909。这个指标受白底、颜色和裁剪边界影响，不说明关节真实、衣服细节吻合或视觉验收已通过。

浏览器实测载入、播放、手脚放大、骨骼与网格开关、插值播放、82→59 循环步进。

## 导出中发现并处理的问题

Spine CLI 导入到已存在 `.spine` 会追加骨架。重复导出调试导致误读旧骨架；已改为 `export_r2.py` 每次使用新建 staging 工程，断言 JSON 导出数量为 1，然后复制最终包。最终工程只有一个骨架。不要复用之前的同名目标直接导入。

## 重建顺序

在实验目录运行：

```powershell
node build_candidate_r2.cjs
py -3 fit_surface_r2.py
node fit_ik_r2.cjs
node quantize_spine_r2.cjs
node apply_surface_r2.cjs
py -3 export_r2.py
node audit_r2.cjs
$env:CANDIDATE_DIR='candidate_r2'
py -3 render_candidate.py
```

网格残差必须在已量化的骨骼动画上计算，`apply_surface_r2.cjs` 会先清除上一轮 deform 再重建，避免叠加。默认骨长/平移为 Spine 存储精度，缩放轨道三位、时间四位。

## 当前边界

这是人工参考标注、IK 与动画专用网格修形结合的小样。脚掌不再刚性，其内部距离会随投影形变；保留原像素不等于保持每个表面像素在屏幕上的形状不变。

PSD 和原视频画风、手脚轮廓、裤衩细节仍不完全一致。遮挡位置与关节中心有推定。没有证明换一段视频能自动得到等效效果，也没有进行换装或移动端性能验收。仅用户可以确认视觉验收。
