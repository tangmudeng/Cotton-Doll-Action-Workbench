# 05 自动化流程与验收约束

## 目标与顺序

以 pixel_sync_20261120 为制作规范，复用规范而非样板坐标。右前 r6、右后 r4 已由用户在 Spine 中验收，保留为不可覆盖的基准。

1. 视频分析：识别角色、动作区间与关键姿势，并提出循环片段。已实现本地运动/重复性区间建议、五帧对照、视频预览与手动调整；角色与关节语义识别仍在确认区间后的视觉模型阶段执行。区间算法不宣称理解动作语义。
2. 部件拆分：七类逻辑部件，逐帧识别和分割，追踪身份及遮挡。只提取源视频已有像素，允许多帧附件，不补画。已有实现；复杂遮挡与不同动作的可靠性仍需验证。
3. 姿态与 IK：肩、髋、肘、膝、手脚端点，整段时序拟合与遮挡不确定性诊断。不能以皮肤重合证明骨骼正确。
4. 蒙皮与动画：按实际姿态绑定，附件、骨骼和 IK 使用相同时间点 stepped 同步。适配双足角色保持 16 骨骼、4 双骨 IK。
5. 自动质检：覆盖缺口、归属歧义、端点支持、漂移与弯曲方向检查已实现；新增首尾源图和关节跳变数值诊断；语义接缝质量仍需视觉核对。明确不确定帧，结构失败不得绕过。
6. 导出：真实 Spine 导入回导、来源记录、报告和预览。技术成功与用户视觉验收分开记录；新视频必须重新识别和验收。

## 本轮完成：统一入口与版本一致性

- 六阶段状态条与随状态变化的主操作按钮。
- 手工纠错默认关闭；自动生成与恢复选项收纳，检查页仍能逐帧查看皮肤与骨骼。
- 后台完成后进入动画核查；载入工程自动查询任务状态。
- 修改输入立即隐藏旧检查链接、清除旧下载及旧运行时预览、取消验收勾选。
- 预览只加载当前 builtRevision；异步载入完成后再次核对工程、版本与资源身份。
- 导出比对构建工程 ID、revision 和包含源身份/姿态/轮廓的输入指纹，拒绝打包错工程或旧输入。
- 日志固定高度；验收只针对指定工程版本。

## 后续推进

已接通区间建议→自动制作→检查包→人工验收→正式导出。下一阶段提高困难遮挡和不同动作的识别质量，并完整验证右前睡觉。均匀背景单角色是当前范围；复杂背景、多角色和视角切换不能宣称已支持。

## 本轮验证

12 项前端流程状态检查；9 项自动化回归；5 项管线回归（包括真实 Spine CLI、隐藏附件、来源隔离、旧版本和错输入拒绝）。浏览器实际载入右后 r4，核对主流程和正式导出入口。

## 全流程接入补充

新增 pixel_video.py，按视频 SHA 缓存分析，区间输出不继承验收。工作台可选择已有视频，不必反复上传。新增 review-export：先输出真实 Spine 待验收包，核对后才正式登记验收。原视频同源机器识别缓存可复用，严格核对源身份、帧哈希、模型和版本；最终骨骼、绑定、预览和验收重新生成。
